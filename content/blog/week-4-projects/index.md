The site now has a projects page. It's short: this website itself and a small Python trainer I wrote. Making the page took an evening. Writing two honest paragraphs about my own code took longer.

The first draft of each description was a feature list: what the program does, bullet by bullet. Technically true and completely unreadable. Nobody opens a student's projects page to study a spec. The questions a visitor actually has are simpler: what is this, why did you make it, what did you learn. Rewriting around those three questions cut the text in half and made it better.

There's also a temptation problem. When you describe a project, every sentence wants to grow an adjective. A console program for memorizing terms becomes an "efficient learning solution". I caught myself doing this and deleted every word that sounded like a press release. A small program is allowed to be a small program. The interesting part is what it taught me, not its imaginary market position.

One thing I appreciated: the projects section forced me to look at my old code with a reader's eyes. The Python trainer had no README, one comment in three hundred lines, and a function called `do_stuff2`. If a project is worth showing, it's worth thirty minutes of cleanup. I renamed things, wrote a README and felt the difference immediately, because the site description almost wrote itself after that.

The projects list being short doesn't bother me. Two real entries beat six padded ones, and the list has nowhere to go but up. First-year is a good excuse that expires soon.

Next week is the big one: making the whole site speak Russian and English, and a final post about how this month went.
