Месяц жизни этого сайта на Hugo кажется достаточным опытом, чтобы объяснить, что такое генераторы статических сайтов и почему для персональной страницы я бы советовал именно их.

Классический сайт, скажем на WordPress, собирает каждую страницу в момент запроса. Программа на сервере принимает запрос, читает контент из базы данных, оборачивает его в шаблон и отдаёт HTML. Это гибко, и это же причина, по которой таким сайтам нужен хостинг с PHP и базой, обновления и страница входа, в которую круглосуточно тычутся боты.

Генератор статических сайтов переносит всю эту работу на мой ноутбук. Hugo берёт папку с файлами Markdown и шаблонами и один раз, на этапе сборки, производит готовые HTML-файлы. У сервера остаётся одна обязанность: раздавать готовые файлы. Взламывать нечего, обновлять на сервере нечего, а хостинг статики настолько дёшев, что GitHub раздаёт его бесплатно.

Рабочий процесс в итоге похож на программирование, и мне это нравится. Контент живёт в git-репозитории. Я пишу пост, делаю коммит, пушу, и GitHub Actions пересобирает сайт автоматически. Вся «админка» — мой текстовый редактор.

Hugo не одинок. Jekyll — ветеран, который сделал подход популярным, и GitHub Pages понимает его без настройки. Eleventy — минималистичный вариант на JavaScript. Astro — модный новичок. Я выбрал Hugo по двум причинам: он собирает сайт за миллисекунды, и у него уже был академический шаблон со всеми разделами, которые нужны студенческому резюме. Решила, честно говоря, в основном вторая.

Компромиссы настоящие. Ни комментариев, ни форм, ни личных кабинетов, если не приклеивать внешние сервисы. Любое изменение требует пересборки, так что живой магазин на этом не сделать. А начальная настройка предполагает, что тебе привычны терминал и Git, и это отсекает многих.

Но сама форма сделки идеально совпадает с персональным академическим сайтом: контент меняется раз в неделю, читатели только читают, бюджет равен нулю. Статика выигрывает этот случай вчистую.
